# Security policy

Use only owned test systems and synthetic data. Never publish a real credential or customer transcript.

For a sensitive finding, use GitHub private vulnerability reporting if the repository owner has enabled it; otherwise use a maintainer's published private contact. Do not open a public exploit or secret-bearing issue. The owner must enable a monitored reporting channel before public launch. No response-time SLA is promised.

Supported scope is the current default branch. Include affected version, minimal synthetic reproduction, impact and suggested mitigation. Keep dependencies reviewed and capture resolved versions before a workshop. The demos bind to loopback and are not production authentication examples.
